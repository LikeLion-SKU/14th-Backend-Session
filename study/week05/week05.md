## 1. Repository & JPA 기본

* **Repository**: 데이터베이스(DB)와 통신하는 계층. JPA를 상속받아 기본적인 CRUD 동작을 함수로 사용 가능함.
* **ORM (Object Relational Mapping)**: 관계형 DB와 객체를 연결해 주는 기술. CRUD SQL 쿼리문을 직접 작성하지 않아도 DB와의 상호작용을 도움.
* **JPA**: 자바에서 ORM 기술의 표준으로 사용되는 인터페이스 모음. 개발자는 JPA 스펙에 맞춰 메서드명만 작성하면 되며, 대표적인 구현체로 Hibernate가 있음.
* **JDBC vs JPA 비교**:
    * **JDBC**: 개발자가 직접 SQL 쿼리문을 작성해야 하므로 성능 최적화에는 유리하지만, 유지보수가 어렵고 반복성 코드가 발생함.
    * **JPA**: 객체(Entity)를 통해 데이터를 조작하며, 복잡한 매핑과 유지보수에 유리함.
* **JPQL**: JPA에서 사용하는 객체지향 쿼리 언어. 테이블명이 아닌 엔티티명과 필드명을 기준으로 작성하므로 DB 구조가 변경되어도 유연함.

## 2. JPA 사용자 정의 쿼리 및 기본 메소드

* **쿼리 메소드 방식**: `findByTitleAndWriter`, `findTop2ByTitle`처럼 메소드 이름으로 JPQL 쿼리를 생성하여 실행함.
* **@Query 방식**: 복잡한 정적 쿼리가 필요할 때 메소드 위에 직접 JPQL을 작성함
* **필수 JPA 쿼리 메소드**: `.save()`(저장), `.findById()`(ID로 조회), `.findAll()`(전체 조회), `.delete()`(삭제), `.deleteById()`(ID로 삭제) 등이 있음.

## 3. DTO (Data Transfer Object)

* **개념**: 계층 간 데이터 전송을 위해 도메인 모델(Entity) 대신 사용하는 데이터 전송 객체.
* **@Builder 패턴**: 생성자 방식보다 직관적이고 매개변수 순서에 상관없이 객체를 생성할 수 있게 해줌. 단, RequestDto에는 테스트 목적 외에는 굳이 사용할 필요가 없음.

## 4. Service 계층과 트랜잭션 (Transaction)

* **Service**: 가장 복잡한 비즈니스 로직을 담당하며, Repository 메소드를 호출함.
* **트랜잭션(Transaction)**: 데이터 거래의 안전성을 확보하기 위한 작업 단위. 작업이 모두 성공하면 DB에 반영(Commit)하고, 하나라도 실패하면 원상태로 복구(Rollback)해야 함.
* **ACID 특성**:
    * **원자성 (Atomicity)**: 모든 작업은 모두 성공하거나 모두 실패해야 함.
    * **일관성 (Consistency)**: 완료 후 데이터는 일관된 상태를 유지해야 함.
    * **격리성 (Isolation)**: 트랜잭션은 서로 독립적으로 실행되어야 함.
    * **지속성 (Durability)**: 완료된 결과는 영구적으로 저장되어야 함.
* **@Transactional**: 선언적 DB 트랜잭션 관리를 제공하는 어노테이션으로, public 메소드에만 적용됨. 클래스 단에 선언하면 모든 public 메소드에 자동 적용되고, 특정 메소드 단에만 선언할 수도 있음.

## 5. Controller 주요 어노테이션

* **@Parameter**: Swagger 어노테이션으로, API 명세서에서 요청 파라미터의 메타데이터를 정의함.
* **@RequestBody**: HTTP 요청 Body(JSON 등)를 Java 객체(DTO)로 매핑함.
* **@PathVariable**: URL 경로(Path)에 포함된 값을 메서드 파라미터로 바인딩함.

## 6. 영속성 컨텍스트

* **개념**: "엔티티를 영구 저장하는 환경"이라는 뜻을 가진 눈에 보이지 않는 논리적 개념.
* **엔티티 생명 주기**:
    * **비영속**: 영속성 컨텍스트와 관계없는 새로 생성된 상태.
    * **영속**: 컨텍스트에서 관리되는 상태 (예: `.save()` 저장 시).
    * **준영속/삭제**: 분리되거나 삭제된 상태.
* **영속성 컨텍스트 주요 특징**:
    * **1차 캐시**: DB를 조회하기 전에 1차 캐시를 먼저 확인하여, 데이터가 있다면 쿼리를 날리지 않고 캐시에서 바로 반환함.
    * **쓰기 지연**: 트랜잭션이 지원되는 동안 생성된 SQL을 '쓰기 지연 SQL 저장소'에 모아두었다가 한 번에 처리함.
    * **변경 감지 (Dirty Checking)**: 엔티티 값을 변경하면 컨텍스트가 내부 스냅샷과 비교함. 값이 변경되었다면 자동으로 UPDATE SQL을 생성하므로 별도의 `.update()`나 `.save()` 메서드를 호출할 필요가 없음.
    * **플러시 (Flush)**: 영속성 컨텍스트의 변경 내용을 DB와 동기화(반영)하는 작업. 보통 트랜잭션이 커밋되기 직전에 발생함.
