# 1. Repository
- db와 통신하는 계층. JPA 상속받음으로써 기본적인 CRUD 동작(함수사용)이 가능해짐

# 2. JPA란?
- 자바에서 orm 기술의 표준으로 사용되는 인터페이스 모음

# 3. orm이란?
- Object Relational Mapping의 약자
- 관계형 DB와 객체를 연결해주는 기술

# 4. jdbc vs jpa
- jdbc
  - 데이터베이스와 통신하기 위한 api
  - 개발자가 직접 쿼리문 작성
  - 유지보수가 어려움
  - 반복성 코드 발생
- jpa
  - orm 기술의 표준으로 사용되는 인터페이스
  - 객체를 통해 데이터 조작
  - 복잡한 매핑 작업에 유리
  - jpql 사용
  - 유지보수 쉬움, crud 자동화

# 5. Repository 실습
- 쿼리 메소드 방식
  - JPA는 메소드 이름으로 쿼리를 생성하는 기능을 제공한다
  - 쿼리 메소드는 메소드 이름에 맞는 JPQL 쿼리를 실행함
- @Query 방식
  - 실행할 메소드 위에 정적 쿼리를 작성할 때 사용
  - SQL이 아닌 JPQL 쿼리가 들어가야함

# 6. DTO
- Data Transfer Object의 약자로, 데이터 전송 객체를 의미
- 계층 간 데이터 전송을 위해 도메인 모델 대신 사용되는 객체

# 7. @Builder
- Builder를 사용 가능하게 해줌
- 생성자 방식보다 직관적임
- 생성자와 달리 매개변수 순서에 상관없이 생성 가능

# 8. Service
- 비즈니스 로직을 담당, 가장 복잡한 코드가 들어가는 부분
- Controller는 Service 메소드를 호출, Service에서는 Repository 메소드를 호출함

# 9. 트랜잭션
- 데이터 거래에 있어서 안전성을 확보하기 위한 방법
- 오류 발생 시 모든 작업을 원상태로 복구 (Rollback)
- 모두 성공 시 결과를 반영 (Commit)

## ACID
- A (Atomicity, 원자성): 모든 작업은 모두 성공하거나 모두 실패해야 함
- C (Consistency, 일관성): 트랜잭션 완료 후 데이터는 일관된 상태여야 함
- I (Isolation, 격리성): 동시에 실행되는 다른 트랜잭션이 영향을 미치지 않아야 함
- D (Durability, 지속성): 트랜잭션 완료 후 결과는 영구적으로 저장되어야 함

## 트랜잭션 선언 위치
- 클래스 단: 해당 클래스의 모든 public 메소드에 자동 적용
- 메소드 단: 해당 메소드에만 적용, 구체적인 설정 가능 (readOnly 등)

# 10. Controller 어노테이션
- @Parameter: Swagger용, 요청 파라미터 메타데이터 정의 (로직에 영향 없음)
- @RequestBody: HTTP 요청 Body를 Java 객체(DTO)로 매핑
- @PathVariable: URL 경로에 포함된 값을 메서드 파라미터로 바인딩

# 11. 영속성 컨텍스트
- "엔티티를 영구 저장하는 환경"이라는 뜻, 눈에 보이지 않는 개념

## 엔티티 생명주기
- 비영속 상태: 영속성 컨텍스트와 관계 없는 새로운 상태 (new/transient)
- 영속 상태: 영속성 컨텍스트에서 관리되는 상태 (managed)
- 준영속 상태: 영속성 컨텍스트에서 분리된 상태 (detached)
- 삭제 상태: 삭제된 상태 (removed)

## 영속성 컨텍스트 특징
- 1차 캐시: 같은 트랜잭션 내에서 동일 엔티티 조회 시 DB 쿼리 없이 캐시에서 반환
- 쓰기 지연: .save() 호출 시 즉시 DB에 쿼리를 날리지 않고 SQL 저장소에 모아뒀다가 flush 시 일괄 전송
- 변경 감지 (Dirty Checking): 엔티티 값 변경 시 별도 .save() 없이도 flush 시점에 자동으로 UPDATE 쿼리 발생
- 동일성 보장: 같은 트랜잭션 내에서 동일 ID로 조회한 엔티티는 같은 인스턴스

## Flush
- 영속성 컨텍스트의 변경 내용을 DB에 반영하는 것 (컨텍스트를 비우는 것이 아님)
- @Transactional 메소드가 정상 종료될 때 commit → flush 자동 발생
