## LIKELION SKUNIV 14TH 백엔드 8주차 세션 정리
### 1. 응답 통일 (Response Unification)
   어플리케이션의 API가 클라이언트(프론트엔드나 외부 서비스)로 보내는 응답 형식을 일관되게 유지하는 작업입니다.

이를 통해 클라이언트는 다양한 API를 호출하더라도 예상 가능한 구조로 응답을 받을 수 있고, 사용성과 유지보수성이 크게 향상됩니다.

응답 통일의 3가지 조건:

BaseResponse<T>: 공통 응답으로 활용할 클래스를 생성합니다.

Controller에서 응답 반환 시 BaseResponse.success(...) 방식 통일.

예외 처리에서 응답 반환 시 BaseResponse.error(...) 방식 통일.

### 2. 프로그래밍 오류 3가지
   컴파일 에러: 컴파일 시에 발생하는 에러입니다. 대표적으로 문법 구문 오류가 있으며, 컴파일 단계에서 발견되어 문제를 바로 알 수 있습니다.

런타임 에러 (Runtime Error): 프로그램 실행 중에 발생하는 에러입니다. 프로그래머가 역추적해서 원인을 확인해야 하며, 철저히 대비해야 합니다.

논리적 에러: 실행은 되지만 의도와 다르게 동작하여 서비스에 지장을 주는 오류입니다. 코드와 알고리즘 체크로 해결합니다.

### 3. 자바의 예외 계층 구조
   Error: 메모리 부족, 스택오버플로우 등 외부적인 요인으로 발생하며 프로그램 코드로 수습 불가한 오류입니다.

Exception: 로직 실수 등 프로그램 코드로 수습할 수 있는 비교적 덜 심각한 오류입니다.

컴파일 예외 (Checked Exception): 반드시 예외 처리를 해야 하며 (안 하면 컴파일 불가) 컴파일 단계에서 확인됩니다.

런타임 예외 (Unchecked Exception): 명시적인 처리를 안 해도 되며 런타임 단계에서 확인됩니다. 개발자는 이 예외가 발생하지 않게 주의해야 합니다.

### 4. Spring 예외 처리
   예외 처리 핵심 코드 구성:

BaseErrorCode: 에러 정보 구조를 정의하는 interface입니다.

GlobalErrorCode: 상황에 맞는 에러 종류를 정의하는 실제 에러 코드 집합(interface의 구현체)입니다.

CustomException: 최상위 예외 객체를 상속받으며 예외 객체(BaseErrorCode)를 품고 있는 클래스입니다.

GlobalExceptionHandler: 어플리케이션 전역에서 발생하는 예외를 한 곳에서 처리하고, 응답 포맷을 통일합니다.

관련 어노테이션:

@RestControllerAdvice: 모든 컨트롤러에서 발생하는 예외를 한 곳에서 처리할 수 있게 해주는 전역 예외 처리기이며, 반환값을 자동으로 JSON 직렬화해줍니다.

@ExceptionHandler: 어떤 예외 클래스를 처리할지 지정하는 애노테이션으로, 인자로 넘긴 예외 타입이 발생하면 해당 메서드가 실행됩니다.

### 5. 유효성 검사 (Validation)
   사용자가 보낸 데이터가 조건에 맞는지 검사하는 것입니다.

Spring에서는 클라이언트가 Controller에 요청을 보냈을 때 요청 본문이 DTO에 매핑되면서 유효성 검사가 진행됩니다 (@Valid 어노테이션이 붙은 경우).

실패 시 MethodArgumentNotValidException이 발생합니다.

주요 제약 어노테이션:

@NotNull: 해당 필드에 null값 불가.

@NotEmpty: 해당 필드에 null, "" 불가.

@NotBlank: 해당 필드에 null, "", " " 불가 (최소 1글자).

@Min / @Max: 해당 필드의 값이 최소/최대값을 벗어나는지 검증.

@Size: 문자열 혹은 숫자의 최소, 최대 크기 검증.
