## 1. Repository 및 JPA 기본
* Repository는 Database와 통신하는 계층입니다.
* JPA를 상속받음으로써 기본적인 CRUD 동작을 함수 형태로 사용할 수 있습니다.
* **JPA (Java Persistence API)**: 자바에서 ORM 기술의 표준으로 사용되는 인터페이스 모음입니다.
* **Hibernate**: JPA 인터페이스를 구현한 대표적인 구현체입니다.
* **ORM (Object Relational Mapping)**: 관계형 데이터베이스와 객체를 연결해주는 기술로, 직접 SQL 쿼리문을 작성하지 않아도 쉽게 데이터베이스와 상호작용하도록 돕습니다.
* **JDBC vs JPA**:
    * **JDBC**: 개발자가 직접 SQL 쿼리를 작성해야 하며 성능 최적화에는 유리하지만, 유지보수가 어렵고 반복 코드가 발생합니다.
    * **JPA**: 객체를 통해 데이터를 조작하며, 복잡한 매핑과 유지보수에 유리하고 CRUD 작업이 자동화됩니다.
* **JPQL**: JPA에서 사용하는 객체지향 쿼리 언어로, 테이블이나 컬럼명이 아닌 엔티티명과 필드명을 기준으로 작성되어 데이터베이스 구조 변경에 유연합니다.
* **사용자 정의 쿼리**:
    * **쿼리 메소드 방식**: JPA가 메소드 이름 규칙을 분석하여 자동으로 JPQL 쿼리를 생성합니다 (예: `findByTitleAndWriter`).
    * **@Query 방식**: 실행할 메소드 위에 정적 JPQL 쿼리를 직접 작성할 때 사용합니다.

## 2. DTO (Data Transfer Object)
* 데이터 전송 객체를 의미하며, 계층 간(Client, Controller, Service 등) 데이터 전송을 위해 도메인 모델 대신 사용됩니다.
* 용도에 따라 `CreatePostRequest`, `UpdatePostRequest`, `PostResponse` 등으로 분리하여 구현합니다.
* **@Builder**: 객체 생성을 직관적으로 만들어주며, 생성자와 달리 매개변수 순서에 상관없이 객체를 생성할 수 있게 해줍니다.

## 3. Service 및 트랜잭션 (Transaction)
* **Service**: 비즈니스 로직을 담당하며 애플리케이션에서 가장 복잡한 코드가 포함되는 계층입니다. Controller가 Service를 호출하고, Service가 Repository를 호출하는 구조입니다.
* **@Transactional**: 선언적 데이터베이스 트랜잭션 관리 방법을 제공하며 클래스 내의 public 메소드에 적용됩니다.
* **트랜잭션(Transaction)의 개념**: 데이터 처리 과정에서 안전성을 확보하기 위해 작업들을 하나의 단위로 묶은 것입니다. 오류 발생 시 모든 작업을 원상태로 복구(Rollback)하고, 모두 성공 시에만 결과를 반영(Commit)합니다.
* **트랜잭션의 특성 (ACID)**:
    * **A (Atomicity, 원자성)**: 트랜잭션 내의 모든 작업은 모두 성공하거나 모두 실패해야 합니다.
    * **C (Consistency, 일관성)**: 트랜잭션 완료 후 데이터는 일관된 상태여야 합니다.
    * **I (Isolation, 격리성)**: 트랜잭션은 서로 독립적으로 실행되어야 하며, 다른 트랜잭션에 영향을 주지 않아야 합니다.
    * **D (Durability, 지속성)**: 트랜잭션이 성공적으로 완료되면 결과는 영구적으로 저장되어야 합니다.

## 4. Controller 코드 변경 및 핵심 어노테이션
* Controller의 반환값을 `ResponseEntity<DTO>` 형태로 변경하여 상태 코드와 응답 본문을 명확하게 전달합니다.
* **@Parameter**: Swagger 전용 어노테이션으로, 요청 파라미터의 메타데이터를 정의하며 실제 로직에는 영향을 주지 않습니다.
* **@RequestBody**: HTTP 요청 Body(예: JSON 형식)를 Java 객체(DTO)로 변환 및 매핑합니다.
* **@PathVariable**: URL 경로(Path)에 포함된 특정 값을 추출하여 메서드 파라미터로 바인딩합니다.

## 5. JPA 심화: 영속성 컨텍스트 (Persistence Context)
* 엔티티를 영구적으로 저장하는 환경을 뜻하는 논리적인 개념입니다.
* **엔티티 생명 주기**:
    * **비영속 상태 (transient)**: 객체만 생성되고 영속성 컨텍스트와 전혀 관계없는 상태입니다.
    * **영속 상태 (managed)**: 객체가 영속성 컨텍스트에 저장되고 관리되는 상태입니다.
    * **준영속 상태 (detached)**: 컨텍스트에 저장되었다가 분리된 상태입니다.
    * **삭제 상태 (removed)**: 데이터베이스 및 컨텍스트에서 삭제된 상태입니다.
* **영속성 컨텍스트의 4가지 주요 특징**:
    * **1차 캐시**: 영속 상태의 엔티티를 캐싱해둡니다. 데이터를 조회할 때 데이터베이스보다 1차 캐시를 먼저 확인하므로 불필요한 쿼리 호출을 방지합니다.
    * **쓰기 지연 (transactional write-behind)**: 영속화가 진행될 때 즉시 쿼리를 보내지 않고 쓰기 지연 SQL 저장소에 모아두었다가 트랜잭션 커밋 시점에 한 번에 전송합니다.
    * **변경 감지 (Dirty Checking)**: 엔티티의 값을 수정할 때 1차 캐시 내부의 최초 상태(스냅샷)와 현재 엔티티를 비교합니다. 변경이 감지되면 자동으로 UPDATE 쿼리를 생성하므로 별도의 `save()`나 `update()` 호출이 필요 없습니다.
    * **동일성 보장**: 같은 식별자를 가진 엔티티를 조회할 경우 완전히 동일한 객체임을 보장합니다.
* **Flush (플러시)**: 영속성 컨텍스트의 변경 내용과 데이터베이스를 동기화하는 작업입니다. 컨텍스트를 비우는 것이 아니며, 트랜잭션이 커밋되기 직전에 내부적으로 자동 발생합니다.
