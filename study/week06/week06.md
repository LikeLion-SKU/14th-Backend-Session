# MySQL과 ERD 활용(연관관계)

## 1. ERD 작성 시 주의해야 할 제약조건
데이터베이스의 일관성과 정확성을 유지하기 위해 ERD 설계 시 다음의 무결성 제약조건들을 반드시 고려해야 함.

* **개체 무결성 (Entity Integrity)**
    * 모든 테이블은 각 행을 고유하게 식별할 수 있는 기본키(Primary Key)를 가져야 함.
    * 기본키는 절대 `Null` 값이거나 중복될 수 없음.
* **참조 무결성 (Referential Integrity)**
    * 외래키(Foreign Key) 값은 참조되는 부모 테이블의 기본키에 실제로 존재하는 값이거나 `Null`이어야 함.
    * 부모 데이터 삭제 시 자식 데이터를 어떻게 처리할지(`Cascade`, `orphanRemoval` 등) 신중히 설계하여 고아 데이터나 의도치 않은 삭제를 방지해야 함.
* **도메인 무결성 (Domain Integrity)**
    * 특정 속성(컬럼)에 들어갈 데이터가 정의된 타입, 크기, 유효 범위 등을 만족해야 함.
    * `Not Null`, `Unique`, 기본값(`Default`) 설정 등을 명확히 정의해야 함.

## 2. 관계형 데이터베이스 (RDB)
데이터를 행(Row)과 열(Column)로 구성하는 데이터베이스 유형

### 주요 요소
* **기본 키 (Primary Key, PK)**: 각 행을 고유하게 식별하는 핵심 키.
* **외래 키 (Foreign Key, FK)**: 다른 테이블의 기본 키를 참조하여 테이블 간의 관계를 형성.

### RDB의 장점
* 직관적인 데이터 구조 
* 데이터 무결성 보장
* SQL 기반 데이터 조회
* 데이터 정규화 지원
* **ACID 트랜잭션** 지원 (원자성, 일관성, 격리성, 지속성).

---

## 3. 연관 관계 (Association)
객체 지향 프로그래밍(참조)과 관계형 데이터베이스(외래키) 사이의 관계 표현 방식이 다르기 때문에 이를 해결하기 위해 **ORM** 기술을 사용하여 매핑함.

### 연관 관계의 방향
* **단방향**: 한쪽 엔티티만 참조용 필드를 가지는 구조. (예: `Post` → `User`)
* **양방향**: 양쪽 엔티티가 서로 참조 필드를 가져 서로 탐색 가능한 구조. (예: `User` ↔ `Post`)

### 연관 관계의 주인 (Owner)
양방향 관계에서는 외래키를 관리할 주체를 정해야 함.
* **주인 (Owner)**: 외래키를 등록/수정/삭제하며, `@JoinColumn`을 사용함. 주로 '다(N)' 쪽이 주인이 됨.
* **주인이 아닌 쪽**: 읽기만 가능하며, `mappedBy` 속성으로 주인을 지정함.

> **TIP**: `@OneToMany`는 객체 상태 관리 부담과 `N+1 문제` 발생 가능성이 있어, 실무에서는 `@ManyToOne` 중심의 단방향 설계를 권장함.

## 4. Fetch Type
연관된 데이터를 데이터베이스에서 언제 가져올지 결정하는 전략

* **즉시 로딩 (Eager Loading)**
    * 엔티티 조회 시 연관 데이터를 한 번에 `Join`하여 가져옴.
    * 쿼리가 복잡해지고 성능 저하를 유발할 수 있음.
* **지연 로딩 (Lazy Loading)**
    * 연관 데이터를 실제로 사용하는 시점에 쿼리를 실행함.
    * 불필요한 조인을 방지하므로 **JPA에서는 지연 로딩 사용을 강력히 권장함**.

## 5. 다중성과 영속성 전이
* **다중성**: 다대일(`N:1`), 일대다(`1:N`), 일대일(`1:1`), 다대다(`N:M`) 관계.
* **다대다(N:M)의 한계**: `@ManyToMany`는 관계 정보(수강일, 성적 등)를 담을 수 없어, 중간에 **조인 테이블**을 만들어 `1:N`, `N:1` 관계로 풀어내는 것이 정석임.

### Cascade & orphanRemoval
* **Cascade**: 부모 엔티티의 영속성 작업(저장, 삭제 등)을 연관된 자식 엔티티에도 전파하는 기능임.
    * **Cascade Type 종류**:
        * `ALL`: 모든 영속성 작업을 자식 엔티티에 전파.
        * `PERSIST`: 부모 엔티티를 저장할 때 자식 엔티티도 함께 저장.
        * `MERGE`: 부모 엔티티를 병합할 때 자식 엔티티도 함께 병합.
        * `REMOVE`: 부모 엔티티를 삭제할 때 자식 엔티티도 함께 삭제.
        * `REFRESH`: 부모 엔티티를 다시 조회할 때 자식 엔티티도 함께 갱신.
        * `DETACH`: 부모 엔티티를 영속성 컨텍스트에서 분리할 때 자식 엔티티도 함께 분리.
* **orphanRemoval (고아 객체 제거)**: 부모와의 연관 관계가 끊어진 자식 객체를 DB에서 자동 삭제.

> **주의**: 부모가 자식의 생명주기를 완전히 관리할 때만 사용해야 함.

## 6. ERD (Entity Relationship Diagram) 설계
데이터베이스 구현 전, 구조와 관계를 시각적으로 설계하는 도구임.

* **구성 요소**: 엔티티(테이블), 속성(컬럼), 관계(연결).
* **논리 vs 물리**: `Domain`(논리적 타입)과 `Type`(물리적 타입 - `VARCHAR`, `BIGINT` 등)을 구분함.
* **관계선 구분**
    * **식별 관계 (실선)**: 부모의 기본키를 자식의 기본키로 사용하는 강한 종속 관계
    * **비식별 관계 (점선)**: 부모의 기본키를 자식의 일반 외래키로 사용하는 유연한 관계

## 7. 실습 도구 및 코드 활용

### 주요 도구
* **MySQL Workbench**: GUI 기반 관리 도구. `Reverse Engineer` 기능을 통해 DB 구조를 ERD로 시각화 가능.
* **ERD Cloud**: 웹 기반 협업 도구. 실시간 설계 및 `Export` 기능을 지원.

### 코드 매핑 예시 (Java/JPA)
`Post` 엔티티에서 `User`와의 `N:1` 관계를 구현하는 방법임.

```java
@Entity
public class Post {
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "user_id")
    private User user;
}
