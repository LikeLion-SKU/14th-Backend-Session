# [Week 06] RDB 설계 및 ERD 활용 정리
## 1. ERD 작성 시 주의해야 할 제약 조건
   ERD 설계 시 데이터의 무결성을 유지하고 효율적인 데이터베이스를 구축하기 위해 다음 제약 조건들을 주의 깊게 고려해야 합니다.

기본 키(Primary Key)의 고유성: 모든 테이블은 행을 고유하게 식별할 수 있는 기본 키를 가져야 하며, 이는 데이터 무결성의 핵심입니다.

외래 키(Foreign Key)와 데이터 관계: 다른 테이블의 기본 키를 참조하여 테이블 간의 관계를 형성하며, 데이터 간의 일관성을 유지해야 합니다.  


다대다(N:M) 관계의 분해: 관계형 데이터베이스는 두 테이블만으로 다대다 관계를 직접 표현할 수 없으므로, 반드시 중간 테이블(조인 테이블)을 생성하여 두 개의 일대다 관계로 분리해야 합니다.

식별 및 비식별 관계의 구분:

식별 관계: 부모의 기본 키를 자식의 기본 키로 사용하여 부모 없이는 존재할 수 없는 강한 결합을 의미합니다.  


비식별 관계: 부모의 기본 키를 자식의 외래 키로만 사용하여 자식이 독립적으로 존재할 수 있는 유연한 구조입니다.  


데이터 정규화: 데이터 중복을 줄이고 체계적으로 정리하여 데이터의 일관성을 유지해야 합니다.  


## 2. 6주차 세션 내용 요약

### Ⅰ. 관계형 데이터베이스(RDB) 개요

개념: 데이터를 테이블(행과 열) 형태로 구성하는 데이터베이스 유형입니다.

이점: 직관적인 구조, 데이터 무결성 보장, SQL 기반의 용이한 데이터 조회가 가능합니다.  


ACID 트랜잭션: 원자성(Atomicity), 일관성(Consistency), 격리성(Isolation), 지속성(Durability)을 통해 안전한 데이터 처리를 보장합니다.

### Ⅱ. 연관 관계 설계 (Association)

객체 vs 테이블: 객체는 참조를 사용하고 테이블은 외래 키를 사용하므로, 이를 연결하기 위해 ORM(JPA) 기술이 필요합니다.  


다중성(Multiplicity): 다대일(N:1), 일대다(1:N), 일대일(1:1), 다대다(N:M) 등 엔티티 간의 관계를 정의합니다.  


연관 관계의 주인: 양방향 관계에서 외래 키를 실제로 관리(등록, 수정, 삭제)하는 주체를 지정해야 합니다.  


### Ⅲ. JPA 최적화 전략

지연 로딩(Lazy Loading): 연관된 데이터를 실제 사용하는 시점에 조회하여 불필요한 쿼리를 방지하고 성능을 최적화합니다.  


영속성 전이(Cascade): 부모 엔티티의 작업(저장, 삭제 등)을 연관된 자식 엔티티에 전파하여 관리 효율을 높입니다.

고아 객체 제거(orphanRemoval): 부모와의 관계가 끊어진 자식 데이터를 자동으로 삭제하여 고아 데이터 발생을 방지합니다.

### Ⅳ. 설계 도구 활용

ERD Cloud: 설치 없이 웹에서 실시간 협업이 가능한 DB 모델링 도구입니다.  


MySQL Workbench: SQL 작성, 데이터베이스 관리 및 리버스 엔지니어링을 통한 ERD 시각화 기능을 제공합니다.
