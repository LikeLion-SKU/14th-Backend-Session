## 1. 관계형 데이터베이스 (RDB)
- 데이터를 행(Row)과 열(Column)로 구성하여 테이블(Table) 형태로 저장하는 데이터베이스 유형.
- 테이블 간의 관계(Relation)를 통해 데이터를 연결하며, 기본 키(Primary Key)와 외래 키(Foreign Key)로 관계를 형성함.
- ACID 트랜잭션(원자성, 일관성, 격리성, 지속성)을 지원하여 데이터가 정확하고 일관되게 유지되는 데이터 무결성을 보장함.

## 2. 연관 관계 (Association)
- 객체 지향 프로그래밍의 참조(Reference) 방식과 관계형 데이터베이스의 외래 키(Foreign Key) 연결 방식 간의 차이를 매핑하는 개념.
- 이 두 방식 사이의 자연스러운 매핑을 위해 ORM(Object Relational Mapping) 기술을 사용함.
- 방향(단방향/양방향), 연관 관계의 주인, 다중성(Multiplicity) 등의 정의 규칙을 가짐.

## 3. 연관 관계의 주인 (Owner)
- 양방향 연관 관계에서 테이블의 외래 키(Foreign Key)를 관리하는 주체가 되는 엔티티 기준
- 연관 관계의 주인은 외래 키 등록, 수정, 삭제가 가능하며 @JoinColumn을 사용해 지정함.
- 주인이 아닌 쪽은 읽기만 가능(외래 키 값 변경 불가능)하며 mappedBy 속성을 사용해 연관 관계의 주인을 명시함

## 4. Fetch Type (조회 전략)
- JPA에서 연관된 데이터를 DB에서 언제 가져올지 결정하는 성능 최적화 관련 전략.
- 즉시 로딩 (Eager Loading): 엔티티 조회 시 연관된 데이터까지 DB에서 한 번에 함께 조회하는 방식으로, 불필요한 조인으로 인해 성능 저하가 발생할 수 있음.
- 지연 로딩 (Lazy Loading): 연관된 데이터를 실제로 사용하는 시점에 DB에서 조회하는 방식으로, 불필요한 데이터 조회를 방지하여 성능에 유리하므로 권장됨.

## 5. 다중성 (Multiplicity)
- 엔티티 간의 관계에서 한 객체가 다른 객체와 맺을 수 있는 관계의 수를 의미함
- 다대일(N:1, @ManyToOne), 일대다(1:N, @OneToMany), 일대일(1:1, @OneToOne), 다대다(N:M, @ManyToMany)로 구분됨.
- 관계형 DB는 두 개의 테이블만으로 다대다 관계를 직접 표현할 수 없어, 중간 테이블(조인 테이블)을 생성해 일대다와 다대일 관계로 분해하여 구현해야 함

## 6. Cascade & orphanRemoval
1. Cascade: 부모 엔티티의 영속성 작업(저장, 삭제 등)을 연관된 자식 엔티티에도 함께 전파하여 생명주기를 같이 관리하는 기능.
2. orphanRemoval (고아 객체 제거): 부모 엔티티와의 연관 관계가 끊어진 자식 엔티티를 고아 객체로 간주하고 DB에서 자동으로 삭제해 주는 옵션

## 7. ERD (Entity Relationship Diagram)
- 데이터베이스를 실제로 구현하기 전에 데이터 구조와 테이블 간의 관계를 시각적으로 명확하게 표현하는 설계 도구
- 관리해야 하는 대상인 Entity(엔티티), 엔티티가 가지는 세부 정보인 Attribute(속성), 데이터 간 연결을 나타내는 Relationship(관계)으로 구성됨
- 부모 테이블의 기본키를 자식 테이블에서 기본키로 사용하는 식별 관계(실선)와 외래키로 사용하는 비식별 관계(점선)로 관계를 상세히 정의함  

## 8. ERD 제약조건
- 데이터의 무결성을 지키기 위해, 데이터를 입력받을 때 실행되는 검사 규칙
- CREATE, ALTER 문 등을 사용할 때도 설정할 수 있다.
1. `NOT NULL` : 해당 제약 조건 설정 시, 해당 필드는 NULL값을 저장할 수 없음
2. `UNIQUE` : 해당 제약 조건 설정 시, 해당 필드는 중복된 값을 가질 수 없다
3. `PRIMARY KEY` : 해당 제약 조건 설정 시, NOT NULL과 UNIQUE 제약 조건의 특징을 모두 가진다.
4. `FOREIGN KEY` : 해당 제약 조건은 하나의 테이블을 다른 테이블에 의존하게 만든다.
   
    4-1. `ON DELETE`: 부모 테이블에 있는 특정 row가 삭제될 때, 그 값을 참조하고 있는 자식 테이블의 행들을 어떻게 할 것인지 결정한다.
   
    4-2. `ON UPDATE`: 부모 테이블의 PK 값이 수정될 때, 이를 참조하는 자식 테이블의 외래 키 값을 어떻게 할 것인지 결정한다.

5. `DEFAULT` : 해당 제약 조건은 해당 필드의 기본값을 설정할 수 있게 해준다.
